## 实际失败与归因证据

### P0-01：已有真实档位，但查询被 Domain Policy 澄清阻断

输入：“Ⅲ型VICP薄抹灰外保温系统，45mm厚度，不同基层的传热系数有什么区别？”

实际：“想确认一下：请指定这轮要讨论的保温体系或实际基层；可以先整理参考选型框架。”

持久化 Backend 决策：`domainIntent=CLARIFY`、`mutation=NONE`、`toolRoute=['backend:clarify']`、`parserSource=LLM`、`policyReason=EFFECT_NOT_AUTHORIZED`；无 reference_candidates/reference_pages。不能将此错误归为 C 端没有展示已有候选：该轮服务端没有发候选。

明确补问“查询Ⅲ型 VICP 薄抹灰外保温 A3-2 构造，45mm 厚度的正式参考选用表”仍得到同类澄清。各后续指代、原页和厚度追问也未形成正确上下文。

### P0-02：确认知识页到正式 Solution Candidate 的衔接未完成

H5 中明确发送“从上面结果中把 A3-2 和 A3-4 加入方案对比”，实际答复取不到已发布对应条目；页面没有候选卡、已确认工作区或 PDF 成功卡。

为区分语义入口与候选服务，另外通过现有 REST 开始一轮方案，并调用其 query 接口：`specClass=III / thicknessMm=45 / systemHint=VICP薄抹灰外保温 / schemeCode=A3-2 / intent=REFERENCE_LOOKUP`。Backend 返回 `version=2 / candidateSetRevision=1 / candidates=[] / candidateCards=[] / stage=COLLECTING_REQUIREMENTS`。

源码核对：`querySolutionCandidates` 调用正式 thermal candidate 查询；本场景知识页确认档位没有成为返回的 Candidate。源码位置只用于定位，不能仅凭静态观察断言唯一根因。需要 Backend 在真实失败记录上排查 Domain effect/授权解释、正式身份映射与确认知识页到 Candidate 的衔接。不可直接为测试句子添加关键词/正则补丁。

这项结构化补测创建了 **1 个显式开始的未确认 SolutionState**；52 轮咨询没有自动 Confirm。最终 Snapshot=0、Report=0。没有将结构化入口当成自然语言 UAT 通过。
