# VICP 知识库二次优化：原文档导航 + 原始页面 + AI 检索索引（实施计划）

## 一、现状审计结论（不重复实现的部分）

- **Outline 可零成本获得**：`pdf-text.worker.ts` 已用 unpdf 的 `getDocumentProxy()`，返回的即底层 pdfjs `PDFDocumentProxy`，直接可调 `getOutline()/getDestination()/getPageIndex()` 读 PDF 书签 → P0-3 第一优先级无需新依赖（扩展 worker 线程消息协议即可）。
- **渲染需新增唯一依赖 `@napi-rs/canvas`**（预编译二进制，unpdf 的 optional peer），复用同一 pdfjs 实例逐页 `page.render()`。
- 上传链 `createVersionUploadIntent/completeVersionUpload`（objectKey=`knowledge/{date}/{fileId}{ext}`、sha256 校验、内容级去重）可加 `assetRole` 复用；测试已有手工拼最小 PDF 的先例（`pdf-text-extractor.test.ts` createPdfWithPages），可扩展出"带书签/无文本层"fixture。
- 确认的问题：`buildWikiStructure` 用 detectHeading 猜目录并整页绑定 section（`pageSectionIds`）；`pageNumber` 混用物理页/印刷页码；blocks 不写 startOffset/endOffset；`pageImageObjectKey` 从未写入；`publishVersion` 门禁只放行 PARSED/PARTIAL（会卡死浏览版图集）；parseStatus 缺 NO_TEXT_LAYER 语义。

## 二、数据模型（迁移 0028，全部增量）

1. **`knowledge_document_assets`**：`id, documentId, versionId, fileId(FK files), role enum(ORIGINAL|SEARCH_SOURCE|OCR_SOURCE|PREVIEW), isPrimary bool default true, timestamps`；unique `(versionId, role)`；迁移 SQL 内回填：历史 `fileId` 非空版本自动生成 ORIGINAL + SEARCH_SOURCE 两行（INSERT SELECT WHERE NOT EXISTS，同一文件双角色，历史行为不变）。
2. **pages 拆页码**：`physical_page_number int`（回填=pageNumber 后 SET NOT NULL）、`page_label varchar(32)`（回填=`page_number::text`）、`page_title varchar(255) null`；unique `(versionId, physical_page_number)` + index `(versionId, page_label)`；`pageNumber` 列保留过渡。规则：AI 引用/展示用 pageLabel，程序打开页面用 physicalPageNumber；pageLabel 不是整数、禁止 Number()，不假设唯一（TOC+physical 消歧）。
3. **`knowledge_toc_items`**：`id, documentId, versionId, parentId, level, sortOrder, title, pageLabel, physicalPageNumber, source enum(PDF_BOOKMARK|TOC_PAGE|MANUAL|COMPANION_FILE), confidence real?, sectionId? (FK sections set null), status enum(DRAFT|PENDING_REVIEW|CONFIRMED) default PENDING_REVIEW`；index (versionId, sortOrder)。TOC=原文件目录，不由 detectHeading 替代。
4. **`knowledge_page_mappings`**：`id, versionId, originalPageId(FK pages cascade), searchPhysicalPageNumber int, pageLabel?, mappingMethod enum(PAGE_LABEL|TOC_TITLE|MANUAL), confidence real?, verified bool default false`；unique (versionId, searchPhysicalPageNumber)。禁止 Original/Search 物理页硬对齐。
5. **枚举/版本**：`knowledge_parse_status` ADD VALUE `NO_TEXT_LAYER`、`SEARCH_SOURCE_REQUIRED`（无 switch 影响面，仅发布门禁调整）；`parsing_job_type` ADD VALUE `UPGRADE_PARSE`；`knowledge_document_versions` 增加 `usage_mode enum(AI_ENABLED|BROWSE_ONLY) default 'AI_ENABLED'`（历史兼容）。

## 三、解析链重构（document.worker.ts + knowledge-chunking.ts）

1. **Block 级 Section 归属（P0-5）**：新增 `parsePageToBlocks(page)`（逐行：detectHeading 切换 activeSection、detectTableRegions 表格区域沿用）→ `BlockDraft[]`（type/content/**sectionDraftPath(标题路径)**/anchor/metadata）；`buildSectionDrafts(versionTitle, blocks)` 按首次出现生成章节草稿；写库顺序 sections → blocks（**block.sectionId = 自身 sectionDraftPath 解析结果，兜底 root**，同页多个小节各归各）→ chunks 由 blocks 派生（仅超长段落 splitText 1200/150，TABLE/标题块 1:1）。`buildChunksFromPages` 保留为组合包装（现有测试兼容）；`pages.sectionId` = 页面首个 block 的 sectionId（主章节）。buildWikiStructure/pageSectionIds 整页绑定逻辑废除。
2. **双源解析（P0-1/P0-6）**：`handleParseJob` 改读 ORIGINAL asset（无则 version.fileId）：
   - PDF 有文本层 → 现有流程 + 页面预览 + 书签 TOC；
   - PDF 无文本层（仅 PDF 分支：totalTextLength < 阈值，阈值沿用 20 并提为 `env.PDF_TEXT_LAYER_MIN_CHARS`）→ **`NO_TEXT_LAYER`，不再记 OCR_REQUIRED/FAILED**：files→READY、parsing_jobs→COMPLETED result{status:"NO_TEXT_LAYER"}、写 pages（parsedText=null）+ 渲染预览；
   - 有 SEARCH_SOURCE asset → 解析检索源文本页，**构建 page mapping**（优先级：pageLabel 精确 → TOC 标题+pageLabel → 页数相等时 PAGE_LABEL 低置信兜底 → 人工），检索源的 blocks/chunks 通过映射挂到 ORIGINAL pageId（命中可直接回溯原页）；无检索源 → `SEARCH_SOURCE_REQUIRED`；
   - DOCX/XLSX 行为不变。
3. **页面预览（P0-4）**：新增 `src/workers/pdf-page-renderer.ts`（独立 worker thread，模板照抄 pdf-text-extractor）：逐页 load → render(scale=DPI/72) → PNG/WebP → putObject `knowledge/previews/{versionId}/p{physical}.png` → page.cleanup 释放 → 下一页；**concurrency=1、禁止全量页常驻内存**；跳过已有 pageImageObjectKey 的页（幂等）；失败尽力而为（记日志不断主任务）；env：`PDF_PREVIEW_DPI`(默认130)、`PDF_PREVIEW_FORMAT`(png)、`PDF_PREVIEW_ENABLED`(默认 true)。DOCX/XLSX 不渲染。
4. **TOC 书签（P0-3）**：`pdf-text.worker.ts` 协议扩展 `done.outline`（flattenPdfOutline：title/level/physicalPageNumber，经 getDestination+getPageIndex 解析）；解析成功后落 `knowledge_toc_items`（source=PDF_BOOKMARK，**status=PENDING_REVIEW 草稿，绝不覆盖 CONFIRMED/人工条目**）；配套 SEARCH_SOURCE 的书签落 source=COMPANION_FILE。目录页文本解析（TOC_PAGE）按确认进 P1。
5. **UPGRADE_PARSE**：新 jobType + 路由 `POST /versions/:versionId/upgrade-parse`（doc:parse）：重读 OSS（ORIGINAL+SEARCH_SOURCE）重跑解析+预览+TOC 草稿+blocks 重建，**PUBLISHED 版本不降级状态**；`scripts/backfill-knowledge-wiki.mjs` 改投 UPGRADE_PARSE（不要求一次重跑全部）。

## 四、发布门禁（P1，硬拦截+软提示）

新增纯函数 `evaluateVersionAiReadiness(version, ctx{assets, toc, mappings})` → `{eligible, blockers[]}`：
- **硬拦截**：usageMode=AI_ENABLED 且 parseStatus=SEARCH_SOURCE_REQUIRED → 拒绝发布（提示改为 BROWSE_ONLY 或先绑定检索源）。`publishVersion` 门禁放行集合改为 PARSED/PARTIAL/（有检索源时）NO_TEXT_LAYER。
- **软提示**（发布成功但响应带 blockers）：存在 toc_items 但无 CONFIRMED；存在 mappings 但 verified=0。
- BROWSE_ONLY：跳过硬拦截，只有 ORIGINAL 也可发布；因无 blocks 天然不进 AI 检索。usageMode 由 B 端 PATCH 版本设置。

## 五、AI 契约与检索升级（P0-8）

- `WikiHit` 增加 `pageLabel/pageTitle/physicalPageNumber/originalFileId`（searchWikiHierarchy 命中后批量回查 pages + ORIGINAL assets 填充）；`AiSourceRef` 增加 `tocPath?/pageLabel?/pageTitle?/physicalPageNumber?/originalFileId?/pageImageUrl?`（pageImageUrl 在 done.sources 恒 null，由 source-detail 异步预签）；`toAiSources` 展示口径：`《标题》/ tocPath / pageLabel 页`，physicalPageNumber 仅供程序定位。
- `formatKnowledgeContext` 与 `buildSnippet` 位置描述改为 pageLabel 优先（"A5 页"），检索命中 Section 后可通过 sectionId→TOC→pageLabel→ORIGINAL 页回溯。

## 六、读取服务与 API（P0-9，全部增量扩展 knowledge-wiki-read.service，不写第二套）

**Source Detail 新响应**（保留旧 `page{...fullText}` 兼容，注释声明"机器提取文本"）：
```
{ document, toc:{path:[...]}, location:{physicalPageNumber, pageLabel, pageTitle,...},
  original:{fileId, pageImageUrl, previewUrl}, extracted:{text, blocks}, highlights, page(兼容) }
```
toc.path = 命中 sectionId 的最近 TOC 祖先链（无则 sectionPath）；original.fileId = 版本 ORIGINAL asset。

**B 端**（权限沿用 `system:knowledge:doc:list/upload/edit/parse`，不新增权限码组）：
- assets：`GET|POST /versions/:versionId/assets`、`POST .../assets/upload-intent`、`POST .../assets/upload-complete`（body 增可选 `assetRole`，复用现有 intent/complete 校验链；role=SEARCH_SOURCE 完成后提示触发 upgrade-parse）、`PATCH|DELETE .../assets/:assetId`
- toc：`GET|POST /versions/:versionId/toc`、`PATCH|DELETE /toc/:tocId`、`POST /versions/:versionId/toc/reorder`（有序 id 列表）、`POST /versions/:versionId/toc/remap`（按 pageLabel/sectionId 重算 physicalPageNumber/section 关联）
- pages：`PATCH /versions/:versionId/pages/:physicalPageNumber`（人工维护 pageLabel/pageTitle，写审计）
- publish 响应带 blockers；版本 PATCH 支持 usageMode

**C 端/AI**（现有 4 个公开文库路由保留不动）：
- `GET /api/v1/client/knowledge/documents/:id/toc`（只读已发布版本）
- `GET /api/v1/client/knowledge/documents/:id/pages/by-label/:pageLabel`（字符串精确定位）
- 现有 `/pages/:pageNumber` 语义化为物理页定位保留；page DTO 增加 physicalPageNumber/pageLabel/pageTitle/extractedText 别名 + pageImageUrl 真实预签 URL

## 七、测试（覆盖两个真实示例类型）

- **Case A（有文本层图集）**：扩展最小 PDF 构造器加 `/Outlines` 书签 fixture → worker 集成测试：书签提取为 toc_items（PENDING_REVIEW）、物理页解析正确；纯函数：`parsePageToBlocks` 同页多 Section（概述/编制依据/适用范围）Block 归属正确、`buildSectionDrafts`、pageLabel A1/A5/B3/D16/G10 字符串处理（禁 Number）。
- **Case B（转曲印刷 PDF）**：空 content stream PDF fixture → 检测 `NO_TEXT_LAYER`（非解析失败状态、非 OCR_REQUIRED）；绑定 SEARCH_SOURCE 后 `buildPageMappings` 按 pageLabel/TOC 标题对齐（不按物理页硬对齐）；无检索源时 evaluateAiReadiness 硬拦截（AI_ENABLED）/BROWSE_ONLY 可发布。
- 其余：mapper 新字段、evaluateVersionAiReadiness 三态、发布门禁放行集合、现有 447 个测试回归。
