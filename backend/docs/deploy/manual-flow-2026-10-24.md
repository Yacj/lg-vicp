# 已实测的自然对话：销售协助客户选方案

在 C 端新建一个普通对话，按顺序逐句发送。实测使用真实 H5、DeepSeek Chat 和正式发布资料的只读副本；按后台实际已选、确认和 PDF 三页预览核对，没有用 HTTP 200 代替业务通过。

1. 客户第一次听说VICP，你帮我用容易懂的话介绍一下，别太多专业词。
2. 他问跟普通保温板比有什么优势，我怎么回答比较合适？
3. 客户比较在意占厚度，现在资料里有哪些厚度可参考？
4. 他那边是200厚的钢筋混凝土墙，希望传热系数低于0.3，你帮我找个合适的做法。
5. 刚才那套具体用多厚的板？有没有参数和资料能发给客户看？
6. 35毫米那条为什么不能选？是资料有问题，还是产品不能用？
7. 明白了，那先用资料完整的那套。帮我整理一段发给客户的话，说清楚厚度和保温参数。
8. 客户认可这套了，就按这个方案帮我出份PDF。

第 7 句后应实际显示已选 1 个方案。实测采用 25mm 正式参考行：200mm 钢筋混凝土基层，K=0.2322，产品层 R=4，总热阻 R₀=4.3068。35/25mm 冲突记录只供对话核对。

第 8 句后，依次点击“选为最终方案”→“设为最终方案”→“确认生成方案”→“生成技术方案 PDF”→“查看报告”→“预览 PDF”。逐页查看三页内容。聊天不会替代确认按钮。

实测报告按该会话本人的 Snapshot 生成；文件下载按用户要求排除。用途/优势、地区合规及有冲突的第二套正式方案仍受现有资料限制。这一条流程通过不代表整体 UAT 达到 READY。
