## 0. 一句话结论

**数据基础够用，缺的是三样东西：快照指纹（版本证据）、规格映射（型号×λ×厚度）、以及一条"投影 → 人工核对 → 审核 → 发布 → 失效重验"的流水线。**
在不编造来源、不放宽证据门禁的前提下，890 档中 **778 档已具备"页内唯一 + 数值齐全"的身份条件**，但 **0 档具备正式候选资格**，因为规格/构造绑定与版本指纹都还是空的。

### 1.1 关键发现：λ 与型号不是一对一

| 型号 | 产品层 λ | 构造数 | 档位 |
| --- | ---: | ---: | ---: |
| I | 0.005 | 26 | 162 |
| I | 0.0025 | 12 | 78 |
| I | 0.08 | 2 | 12 |
| I | 无 | 3 | 17 |
| II | 0.008 | 26 | 162 |
| II | 0.0025 | 12 | 72 |
| II | 无 | 3 | 17 |
| III | 0.012 | 27 | 165 |
| III | 0.0025 | 12 | 48 |
| III | 0.08 | 2 | 8 |
| III | **0.0012** | 1 | 9 |
| III | 无 | 2 | 8 |
| 未声明 | 0.005 / 0.0025 / 0.008 / 0.08 / 无 | 11 / 8 / 3 / 2 / 4 | 132 |

**含义**：同一型号下存在多个 λ，且 132 档没有型号。因此**不能按"型号→λ"自动生成规格**；必须由甲方给出"型号 × λ_eq × 修正系数 α × 厚度"的对照，否则任何自动绑定都是编造。
（另：`A3-3` 的 λ=0.0012 与同型号 0.012 相差 10 倍，属原文疑点，未擅自修正。）

### 1.2 能否直接复用已有知识页与结构化数据

可以，但要区分"事实"和"资格"：

- **事实可复用**：页 + 结构化系统/档位（构造编码、基层、基层厚度、屋面形态、部位、厚度、R/R₀/K、层信息）已足够支撑只读展示与只读比较，无需重新识别。
- **身份可复用**：`constructionKey + optionFingerprint`（已在只读比较中实现）能稳定定位"页内某档位"，不依赖数组序号。
- **资格不可复用**：快照是 v1（无 revision）、无规格、无图集构造方案、多数无原表行标签。这些必须补，且补的过程必须有人签字。

## 2. 成为正式 Candidate 的最小必要条件（不放松任何门禁）

一条档位要进入 `Candidate`，必须同时具备：

1. **来源页可读**：已发布、AI_ENABLED、当前版本、有权访问（现有校验保留）。
2. **身份唯一**：`(pageId, versionId, constructionKey, thicknessMm)` 唯一；同页重复 → 人工裁定，不取第一条。
3. **版本证据**：快照带 `confirmedRevision`；客户端引用时回传，服务端重算比对，不一致即失效。
4. **数值自证**：厚度 + R + R₀ + K 齐全，且与快照逐项一致（容差 5e-5）。
5. **规格绑定**：`product_specs` 中存在与 `(型号, λ_eq, α, 厚度)` 完全一致的已发布规格；无匹配 → 挂起，不新建。
6. **构造绑定**：`construction_schemes` 中存在该页该系统的正式方案（ATLAS 参考集），`atlas_page` 可回溯。
7. **审核签署**：资料负责人 + 技术复核双签，记录时间、人、依据、驳回原因。

**这 7 条全部满足，才写 `thermal_reference_rows` 并发布；发布后仍是"可确认候选"，不是"已选方案"。**

## 3. 绑定路径（投影 → 审核 → 发布，四步）

```
① 只读投影（不写库）
   页快照 → option identity（pageId/versionId/constructionKey/fingerprint/thickness）
        → 与目录规格做"候选匹配"（只匹配，不创建）
        → 生成差异清单：缺规格 / 缺型号 / 缺 revision / 页码冲突

② 人工核对（B 端工作台）
   逐页核对：印刷页码、构造编码、基层、厚度、R/R₀/K、原表行标签
   逐档裁定：冲突项选唯一身份；无型号项标注"待甲方确认"
   逐档映射：选已有规格，或提交"新规格申请"（含型号、λ_eq、α、依据）

③ 审核发布（双签）
   资料负责人：来源、页码、原文一致性
   技术复核：规格/构造/公式口径、厚度与规格一致
   通过 → 写 ATLAS 参考集 + construction_schemes + thermal_reference_rows（带 source_page_id/label）
         → 状态 PUBLISHED；失败 → REJECTED + 原因

④ 失效重验（每日，只读比对后改状态）
   revision 变化 / 页失效 / 页码不再唯一 / 规格或构造撤回 → DEPRECATED，立即从候选移除
   恢复需重新审核，不自动复活
```

### 3.1 身份在行上的落地方式（避免再加一列 optionId）

`thermal_reference_rows` 目前没有 `option_id` 列。两条路：

- **推荐（不改表）**：读取时用 `(source_page_id, scheme 构造编码, thickness_mm)` 在当前快照里重算唯一档位，得到 `optionId`；唯一才放行，多条即 `AMBIGUOUS`。这样"行"与"页档位"永远指向同一快照，不需要冗余存 ID。
- 备选（加列）：`source_option_key` 存 `constructionKey|fingerprint`，好处是可索引；代价是新增列 + 回填 + 与快照不同步的风险。

本设计选**推荐方案**，因此 P0-B 已有的身份算法可直接复用，无需改表。

### 3.2 规格映射策略（不批量造数）

- 先做**只读匹配**：按 `(specClass, λ_eq, α, thicknessMm)` 与现有 `product_specs` 精确匹配；
- 匹配不到 → 生成"规格申请单"，由甲方确认后逐条创建（禁止按 890 档批量生成）；
- 132 档无型号 → 一律挂起，不推断。

## 4. B 端需要的审核发布流程

| 环节 | 角色 | 输入 | 产物 | 拒绝条件 |
| --- | --- | --- | --- | --- |
| 导入/投影 | 系统 | 已确认页快照 | 候选投影清单（含缺项） | 页不可读 |
| 资料核对 | 资料负责人 | 投影清单 + 原图 | 核对记录（页码/编码/厚度/数值） | 页码不唯一、数值与原文不符 |
| 规格映射 | 产品/技术 | 型号、λ_eq、α、厚度 | 规格申请/绑定 | 型号缺失、λ 冲突、厚度不符 |
| 技术复核 | 技术负责人 | 核对记录 + 映射 | 复核签署 | 构造/公式口径不符 |
| 发布 | 系统 | 双签记录 | ATLAS 参考集 + 方案 + 行（PUBLISHED） | 缺任一必要条件 |
| 失效重验 | 系统（每日） | 快照/页/规格状态 | DEPRECATED 或保持 | 任一证据变化 |
| 审计 | 系统 | 全部操作 | 操作人/时间/依据/前后值 | — |

**B 端必须能看到的四类缺口**：缺型号、缺规格、缺 revision、页码冲突。这与 P0-A 已经产出的 `bindingGapCount / bindingGapFields` 对齐。

## 5. 两个独立验收方向（不得互相替代）

### Track A：知识库查询与对话质量

| 项 | 内容 |
| --- | --- |
| 目标 | 用户问"有没有 K≈0.3 的做法""A3-1 是什么"时，事实正确、范围说清、不编造 |
| 判定点 | 数值与原文一致；指标口径不混；来源可追溯（页/印刷页码）；缺资料时正确拒绝或降级只读；多轮条件不丢 |
| 数据要求 | L0/L1（890 / 794）即可，**不依赖**正式候选 |
| 当前状态 | 可验收，但仍有解析类软件缺陷（UAT 软件类硬失败 45） |
| 通过标准 | 事实准确率、口径正确率、来源可追溯率达标；不出现编造页码/数值 |

### Track B：正式候选与 PDF 业务闭环

| 项 | 内容 |
| --- | --- |
| 目标 | 候选可选 → Confirm → Revision → Snapshot → PDF，权限与审计完整 |
| 判定点 | 候选来自 ATLAS 参考集；Confirm 后不可被新查询篡改；PDF 页数/内容/来源与快照一致；越权被拒 |
| 数据要求 | **L3 ≥ 1 条**（规格 + 构造 + 原页 + revision + 审核） |
| 当前状态 | **不可验收**：L3 = 0，且 0 档有 revision |
| 通过标准 | 全链路真实 H5/小程序跑通 + 审计可查 |

**判定规则**：两条各自打分，任一未通过 → 整体 NOT_READY；Track A 通过不能替代 Track B，反之亦然。

## 7. 结论

- **不需要放宽任何门禁**：7 条必要条件全部来自现有校验，只是把"缺哪一条"显式化。
- **不需要批量造数**：778 档可作为投影候选，但必须逐页核对、逐条映射规格。
- **不能一步到位**：先补齐版本指纹与页码唯一性，再逐批（建议每批 1 页 ≈ 9–12 档）审核发布。
- 在 L3 ≥ 1 且 Track B 跑通之前，整体发布状态保持 **NOT_READY**。
