# C端 AI 完整参考页与确认档位

本轮扩展现有 AI 工具、SSE、消息元数据和来源详情，不增加接口、迁移或匹配算法。

2026-10-11 销售/设计院阅读优化：C/PC 正式数值查表文案只强调厚度与所问指标，K 查询不再重复双 R 及“已确认记录”等内部表述；保留来源和工程选用说明。`answerStyle=THERMAL_SOLUTIONS` 只标记确定性查表摘要，客户端可在正式模型/ID/answerOffset 可定位时以方案卡替换该摘要，普通知识解释不得删除。`primaryFieldKeys` 由现有 filters 投影，仅控制优先显示，不改变匹配、数值或 fieldKeys 高亮。两字段随 URL-free 元数据保存并在有效来源恢复，旧消息没有标记时保持原正文。B 端 test-qa 默认文案保持原契约。C 端默认显示前两项既有有序候选，其余展开；参考页呈现整页连续表格，构造简图仍在完整原图。

## 正式事实与页面

- `thermal LOOKUP_CANDIDATES` 仍查询正式发布的热工行。只有同来源页、同构造、厚度/产品层R/总R/K全部一致且唯一的确认档位，才绑定 `constructionId/optionId/fieldKeys`；冲突不补算、不猜高亮。
- 知识检索回退保留原有资料选择。明确数值查表在已选且有权检索的当前发布版本中读取完整确认快照，复用既有 Parser/Matcher，按整条档位确定性生成回答。完整行优先预算，不通过AI正文或旧 parsedText 查找数字。
- C端不消费B端草稿 test-qa范围。正式来源必须当前 `PUBLISHED + ACTIVE + AI_ENABLED`，未删除、生效中且属于平台或会话项目；先校验再签名。
- `renderModel`保留该页所有构造、层和厚度。只有实际引用行进入matches，四项正式数值、字段高亮及回答位置来自同一记录。
- Agent保留原工具选择、人工选择等待、计算与报告流程。确认查表结果在最终正文输出前替代模型的数值复述，SSE隐藏定位标记，返回 `answerOffset` 供C端插入对应回答段落。
- 普通原页/构造参数追问继续原回答链，返回完整表格及正式行标识。图片无可用坐标时不伪造框选，构造简图保留在完整原图中。

## 消息与来源详情

- `reference_pages`返回完整页面；`done.referencePages`保留同页多命中与完整模型，兼容原有平铺消息引用格式。C端现有归一层合并两种结构。
- `metadata.referencePages`只保存标识、确认模型、匹配、来源objectKey；不保存临时签名URL。
- `GET /ai/conversations/:id`在会话归属校验后批量读取引用页、重新校验发布状态并重签原图，返回各消息 `referencePages`。撤回、换版、越权和旧快照ID失效的引用省略，明确空数组阻止客户端复活旧缓存。
- 旧消息没有档位ID时仍可查看原图；不利用旧摘要数字推测新页面的高亮。
- `GET /ai/knowledge/source-detail`沿用原有文档/项目守卫，返回 `page.renderModel`和新签名原图。仅浏览版本及尚未生效的资料在签名前拒绝。图片临时不可用仍保留表格，客户端可以重新请求续签。
