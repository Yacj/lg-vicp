# 后台当前状态

> 本文档记录 `lg` 仓库当前代码状态，不把页面规划、数据库表、worker 或内部 service 计为可访问的后台产品能力。
>
> 证据优先级：运行时注册与真实 HTTP 路由 > 当前前端源码 > 持久化 schema/worker > 规划文档。后端只读核对，前端工作区已有未提交改动必须保留。

## 1. 完成度口径

| 状态 | 判定标准 |
| --- | --- |
| **已实现基础设施** | 能独立运行并为后续页面提供稳定能力，但不代表某个业务页面已经交付。 |
| **仅壳层/空态** | 有页面骨架、视觉结构或空状态，但没有正式业务数据闭环。 |
| **后端已有但前端未实现** | 后端存在可调用接口，前端没有对应页面或业务接线。 |
| **后端部分实现** | 后端只覆盖业务的一部分，或页面只能安全实现窄路径。 |
| **接口缺失** | 没有可供前端调用的 HTTP 契约；不能用数据库、worker、内部 service 或静态数据替代。 |

当前不能使用“后台已完成”作为总体结论。真实状态是：基础壳层和认证基础设施已形成，工作台仍是诚实空态，系统管理中的字典、部门、岗位和菜单页面已按真实接口接入，其他大多数业务页面尚未接入，知识库后台被接口缺口阻塞。

## 3. 基础壳层实际完成范围

### 3.1 布局与响应式

`AdminLayout` 根据外观设置和断点选择以下布局：

- **侧边布局**：左侧 `AppSidebar`，右侧 Header、Tabs 和内容区。
- **顶部布局**：Header 内承载一级导航，Tabs 和内容区位于下方。
- **混合布局**：Header 承载一级导航，当前模块的上下文菜单使用侧栏。
- **双侧栏布局**：一级菜单和上下文菜单由 `AppDualSidebar` 分层承载。
- **移动态**：窗口小于抽屉断点时覆盖设置布局，使用 Header + `AppMobileNavigation` 抽屉；导航变化后自动关闭抽屉。

当前布局是通用基础设施。它不证明动态业务菜单已经可访问。

### 3.2 Header、Tabs 和用户入口

Header 当前真实行为：

- 全局搜索只搜索已投影的可导航菜单。
- 刷新使用 Tabs store 的 refresh 版本机制。
- 全屏依赖浏览器 Fullscreen API。
- 主题切换修改外观 store。
- AI 入口只有在动态菜单中存在可导航 AI 页面时才启用。
- 通知按钮禁用。
- 用户面板中的“个人信息”“账号设置”“修改密码”均禁用；当前仅支持用户摘要和退出登录。

Tabs store 已实现：

- 根据路由元数据打开/更新标签。
- 固定标签与普通标签的关闭保护。
- 关闭当前、其他、左侧、右侧、全部。
- 固定/取消固定、移动、刷新和可缓存路由名投影。

### 3.3 外观设置与图表

外观设置包括主题模式、系统/组件主题色、布局模式、侧栏主题、内容宽度、密度、Tabs 样式、圆角、固定 Header、显示 Tabs 等字段。配置经过解析后持久化，不依赖后端。

图表层已具备：

- `AppChart`、`AppChartPanel` 和 option 工厂。
- 图表 token 与深色主题适配。
- 工作台趋势、任务分布和 fallback 柱图的渲染条件。

但是工作台当前没有真实 `Dashboard` 汇总数据，因此图表组件只负责“有数据时如何显示”，不应被描述为业务图表已完成。

## 4. 认证、权限和动态路由

### 4.1 认证与 Token

前端使用真实接口：

- `GET /api/v1/auth/b/captchaImage`
- `POST /api/v1/auth/b/login`
- `GET /api/v1/auth/b/getInfo`
- `GET /api/v1/auth/b/getRouters`
- `POST /api/v1/auth/refresh`
- `POST /api/v1/auth/logout`

登录时校验 `B_ADMIN` 客户端和允许进入 B 端的角色。HTTP 401 或业务 401 进入单次刷新流程；刷新失败清理本地会话并回到登录页。

### 4.2 RBAC 与资源边界

前端已具备：

- 用户权限集合、角色集合和能力摘要的状态承载。
- `hasPermission`/`hasAnyPermission` 等权限判断。
- 动态页面的 `meta.permissions` 路由守卫。
- 动态菜单按钮节点投影为按钮权限集合。
- 页面级和操作级权限组件/指令基础设施。

限制：

- 按钮权限投影已经存在，但运行时主要读取用户权限；不能把“菜单节点被投影”理解为后端授权。
- 项目、文件、报告、分享和 AI 会话还必须服从后端项目可见性或资源归属规则。
- `NORMAL_USER` 不能进入 B 端；`CHANNEL_USER` 可以登录但只能管理自己创建的项目。

### 4.3 动态菜单风险

动态菜单投影的实际行为必须明确记录：

1. 目录节点可能保留 `path`，但目录本身不注册页面路由；如果目录没有可导航子菜单，可能形成无效导航。
2. 页面节点的 `component` 未命中本地 `componentMap` 时会被丢弃，不会动态执行任意 import 路径。
3. 路由守卫发现投影问题后，告警通知代码目前被注释，用户可能只看到菜单缺失而没有明确反馈。
4. 当前 `componentMap` 由构建期 `import.meta.glob('../views/**/*.vue')` 生成，覆盖所有现有页面，并保留 `Home` 等兼容别名；菜单表单允许展示 `@/views/...vue` 文件路径，但提交前必须归一化为已枚举 key。
5. 菜单图标不执行任意组件名或资源路径解析：TDesign 图标来自包内 `manifest`，本地 SVG 通过 `src/assets/menu-icons/index.ts` 显式登记，历史裸值只映射到已知图标，未知值使用 fallback。
6. 动态菜单不允许由静态硬编码菜单长期掩盖后端菜单缺失。

## 5. 页面与业务完成度

### 5.1 工作台是诚实空态

工作台源码明确创建空的 `DashboardOverview`，原因是后端没有 Dashboard 聚合接口。当前事实：

- 没有正式指标数据。
- 没有正式待处理事项。
- 没有正式知识处理管线统计。
- 趋势切换函数只保留未来接线位置，没有按范围请求数据。
- 趋势图和任务分布图在没有数据时不渲染业务图表。
- 不通过并发调用项目、会话、反馈或任务列表拼装平台总览。

因此工作台只能计为**仅壳层/空态**，不能计为工作台业务完成。

### 5.2 系统基础数据已完成

后端真实能力：

- 字典：动态字典与字典项完整 CRUD，修改/删除/字典项变更会使后端缓存失效；没有“手动刷新缓存”接口。
- 部门：列表、树、创建、编辑、状态变更、删除和用户按部门查询能力存在。
- 岗位：服务端分页列表、创建、编辑、状态变更和删除存在；没有岗位成员查询接口。

前端已完成：

- 字典：API、类型、composable 和页面已完成，使用真实全量字典列表并在前端进行确定性筛选/分页；字典项独立请求和维护；权限码 `system:dict:*` 控制操作可见性。
- 部门：API、类型、composable 和页面已完成，接入真实树、CRUD、状态、搜索（保留祖先链）、父级排除自身及后代、成员查看（需 `system:user:list`）。
- 岗位：API、composable 和页面已完成，服务端分页、CRUD、状态切换，无后端不支持的筛选与成员功能。
- `component-map.ts` 已通过构建期 `import.meta.glob('../views/**/*.vue')` 枚举所有现有页面，兼容 `Home` 与历史内部 key；菜单表单显示可读文件路径，但最终提交统一为白名单 key。
- 以上页面可通过后端菜单动态投影访问，产品链路完整。

### 5.3 系统菜单与权限资源

- 菜单管理使用 `GET /api/v1/platform/menus` 的扁平列表，自行构建稳定排序的树形 `AppDataTable`；新增、编辑、删除、启停均按后端真实字段和路径执行。
- 抽屉表单按目录、菜单、按钮类型动态收敛字段，使用响应式两列布局，小屏退回单列；组件输入可以手动填写或选择可读路径，但最终必须命中 `componentMap` 白名单并转换为内部 key。
- `DIRECTORY` 不注册页面路由，内部 `MENU` 只允许 `componentMap` 白名单组件，外链 `MENU` 只允许 HTTP(S) 并通过新窗口打开，`BUTTON` 只投影为权限码。
- 菜单图标统一由 `AppIcon` 渲染：TDesign 图标来自 `manifest` 注册表，本地 SVG 通过 `src/assets/menu-icons/index.ts` 显式登记，旧裸值只映射到已知图标，未知值安全 fallback。
- 权限码在菜单表单中自由输入；前端只校验非空、长度、空白和字符格式，按钮必须填写，不用 `/api/v1/platform/permissions` 的集合阻止保存；权限资源接口仍供角色权限等业务使用。
- 菜单变更后重新获取运行时菜单；失效动态路由、当前标签和当前页面会按安全回退规则收敛。

### 5.4 后端已有但前端未实现的主要模块

后端已有真实接口但当前前端没有完整业务页：

- 角色、权限、用户。
- 项目列表、我的项目和项目详情基础操作。
- 文件上传、完成、处理状态、下载和删除。
- AI 对话、SSE 消息、停止、反馈、重新生成和报告草稿。
- AI 服务商、模型、场景绑定、提示词。
- AI 会话运营与反馈。
- 审计日志、登录日志、在线用户、缓存和 cron 任务。

它们可以按 `api-gaps.md` 和 `next-implementation-plan.md` 的边界进入开发，但不能在页面地图中标记为已实现。

## 6. 代码真实性与已知检查结论

### 6.1 Mock 边界

生产源码中未发现用于填充业务列表、统计或成功响应的随机业务 Mock。测试源码中的 mock 主要是浏览器 API、网络客户端或组件依赖的替身，不代表生产业务数据。

### 6.2 已确认的 UI 风险

- 当前检查未发现明确的深色模式漏底问题。
- 登录页装饰线在窄屏存在横向溢出风险，需要在登录页专项验证中处理。
- 安装版 TDesign 类型声明确认 `RadioGroup` 的 `default-filled` 合法，不应把该属性误报为本轮缺陷。

### 6.3 依赖与工具链

已核对当前依赖使用情况：未发现需要在本轮审计中清理的源码直接依赖；仍需工具或产品确认的接线项不通过删依赖解决。当前仓库使用 TypeScript 7 与 `vue-tsc`/`typescript-eslint` 的兼容性仍需单独处理，不能通过回退用户已有依赖文件掩盖。
